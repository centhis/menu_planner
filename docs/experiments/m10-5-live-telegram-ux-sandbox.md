# Stage 10.5 live Telegram UX sandbox shell

Date: 2026-07-13

## Goal

Build the first live Telegram UX sandbox shell without changing active Menu
Planner business state.

Important framing update: this artifact records product UX/UI creation for
Menu Planner in Telegram, not a throwaway technical experiment. The sandbox is
the safe runtime surface; the accepted screens, labels and navigation rules are
first-class UI decisions for the application.

The shell must:

- open from a user-visible Telegram interaction;
- label all data as demo and not active state;
- provide navigation between the primary menu-planning states;
- use inline buttons with user-visible Russian action labels through a
  Hermes-supported callback flow;
- avoid full payload callback data.

## Runtime evidence

Sanitized runtime facts:

- Hermes container is running.
- Telegram Gateway configuration has `TELEGRAM_BOT_TOKEN=<set>` and
  `TELEGRAM_ALLOWED_USERS=<set>`.
- The host `plugins/menu-planner` package exists, but the current
  `config/hermes-managed-config.yaml` enables only `dashboard_auth/basic`.
- Current `compose.yaml` does not mount `plugins/menu-planner` into Hermes.
- Hermes Telegram adapter registers a `CallbackQueryHandler`.
- Hermes Telegram adapter supports built-in callback namespaces including
  `sc:*` for slash confirmations and `cl:*` for clarify choices.
- No generic project-owned `ux:*` callback namespace was found in the
  installed Hermes Telegram adapter.
- After a soft `docker compose restart hermes`, the Gateway still logged some
  Telegram polling/network reconnect warnings (`RemoteProtocolError`), but the
  user-visible Hermes-native clarify flow later completed successfully.

No token, Telegram user id, chat id, message id, or private payload is recorded
in this report.

## Direct Bot API attempt

An initial host-owned sandbox helper sent a Home screen directly through the
Telegram Bot API with callback data shaped as `ux:*`.

Result:

- Home screen delivery succeeded in live Telegram.
- The user clicked the inline button.
- Callback was not received by the helper within the polling window.
- This path is not accepted for Stage 10.5 callback handling.

Reason:

The live Hermes Gateway owns Telegram update polling. A sidecar Bot API polling
script competes with the gateway and cannot share Hermes in-process callback
state. In addition, Hermes does not route arbitrary `ux:*` callbacks.

## Accepted shell path

Use Hermes-native `clarify` for the Stage 10.5 UX sandbox shell:

```text
Telegram user message
-> Hermes Telegram Gateway
-> Hermes agent/tool loop
-> built-in clarify tool
-> sandbox adapter registers clarify_gateway state
-> Telegram inline keyboard with Russian action labels
-> inline callback data cl:<clarify_id>:<choice_index>
-> Hermes callback handler
-> visible Telegram edit/response
```

This is simpler than custom Telegram Bot API polling and uses the installed
Hermes callback path.

## Sandbox command

The user-visible entry command is:

```text
Открыть UX-песочницу Menu Planner
```

The reproducible prompt for the live smoke is generated by:

```bash
python3 scripts/m10_5_live_telegram_ux_sandbox.py --prompt
```

The prompt instructs Hermes to:

- use the built-in `clarify` tool;
- show the Home screen as a Telegram clarify prompt;
- offer exactly one `Составить меню` choice;
- after the click, show the generated menu screen;
- then offer `Покупки` as the next natural choice;
- avoid terminal, files, web, external APIs and active state changes.

## Screens

Scenario analysis:

- Empty-home planning: open sandbox -> `Составить меню` -> see a usable
  weekly menu preview. One tap after entry.
- Return after planning: menu preview -> `Главная`; the main screen switches
  to the active-menu state.
- Home with menu: if a menu already exists, the home screen should stop being
  a generic start screen. It should show:
  - remaining not-yet-bought shopping items;
  - recipe for the current meal slot;
  - primary action `Изменить меню`, not `Составить меню`.
- Menu preview actions: no generic confirmation button; the preview returns to
  `Главная` or opens `Изменить меню`.
- Menu correction: active home -> `Изменить меню` -> type a natural-language
  change. The sandbox captures text and shows a preview example.
- Shopping: active home -> `Покупки`. The button appears on the main screen
  only when a menu exists.
- Settings: home -> `Настройки`; settings never trigger menu generation
  directly.
- Food preference edits: `Настройки` -> `Изменить питание`; text input is for
  food habits and restrictions only.
- Store sources: `Настройки` -> `Источники цен`; stores are not entered as
  free text. The UX treats each store as a managed source backed by a separate
  Hermes skill, but sources are not all enabled by default. The user selects
  only the needed stores.
- Store selection: `Источники цен` -> `Выбрать магазины`; Telegram shows
  selected, available and disabled sources with explicit connect/disconnect
  actions.
- Store refresh: `Источники цен` -> `Обновить сейчас`; in Stage 10.5 this is a
  demo action only and runs only selected sources in the product. It does not
  fetch store pages, prices or availability in Stage 10.5.
- Shopping with multiple sources: when 2+ price sources are selected, shopping
  items are grouped by source. With one selected source, the product can show
  one plain shopping list.
- Text edit help: explains how settings should be changed by normal text,
  then returns to settings or home.
- Settings text entry: when the user types a settings change from `Настройки`
  or `Изменить настройки`, the UX sandbox captures the text, shows a demo
  notice, and returns to `Настройки`. It must not fall through to the generic
  Hermes agent.
- Errors: short recovery screen with no raw stack trace or internal state.

Accepted changes reflected in sandbox:

- Unsupported `ux:*` callbacks were removed from the target UX path.
- The sandbox uses Hermes-native `clarify` / `cl:*` callbacks.
- Demo labels and draft-vs-active separation are repeated on every core screen.
- Step 5 previews were switched from English text descriptions to Russian
  structured Telegram-style previews.
- Unsupported custom preview callbacks were removed from the target demo path.
- The full interactive demo prompt now routes buttons through Hermes `clarify`.
- Bare numeric button labels are rejected for product UX. The live sandbox must
  show Russian action labels on inline buttons and keep numeric choice indexes
  only inside hidden `cl:*` callback data.
- Numeric Hermes `send_clarify()` fallback is disabled for the UX sandbox.
  The sandbox must not show `1/2/3/Other` buttons as a recovery path.
- Text-labeled sends use extended Telegram request timeouts and retries to
  reduce transient fallback pressure.
- Telegram send timeouts are treated as uncertain delivery: the sandbox
  registers `cl:*` callback state before send and keeps it after retry
  exhaustion, because Telegram may still display the message even when the API
  client did not receive a successful response.
- The old engineering-first flow is rejected for product UX. Visible screens no
  longer lead with status, draft, cancel confirmation or `confirmation_id`
  language.
- The accepted direction is a lightweight menu-planning flow:
  `Составить меню` -> `Меню составлено` -> `Главная`. Once menu exists, the
  main screen shows `Покупки`, `Рецепт`, `Изменить меню` and `Настройки`.
  `Изменить меню` is text-first: the user writes what to change, then sees a
  preview before any save in the product.
- The choice tree was audited after user feedback that settings unexpectedly
  contained `Составить меню`. The settings branch now has only
  `Изменить текстом` and `Назад`; it cannot navigate directly to
  `menu_ready`.
- User requested state-aware home behavior after menu generation. Accepted UX
  direction: when a menu exists, home shows remaining shopping items and the
  current meal recipe, and the primary action changes from `Составить меню` to
  `Изменить меню`. In the current sandbox this can be represented with demo
  session state; in production it must come from Application read APIs.
- Text-based settings are allowed only as an ergonomic UX direction, not as a
  privileged instruction channel. They are treated as untrusted user input and
  must be parsed into a narrow settings/change-intent schema before any model
  or tool action.
- The sandbox now intercepts free text while the active screen is `settings`
  or `settings_edit`. It responds with a bounded preview such as
  `Понял: 1 человек.`, notes that demo values are not updated, and then
  re-renders the settings screen.
- The accepted narrow-bot direction removes the global `Закрыть` inline button
  from all sandbox menus. The demo stays inside Menu Planner navigation;
  leaving the chat or restarting the launcher is enough for this Stage 10.5
  sandbox.
- Free text on button-only screens is blocked inside the sandbox adapter and is
  not forwarded to the generic Hermes agent. This prevents accidental use of
  the Menu Planner bot as a general prompt box.
- Free text on text-first screens remains untrusted user data. Production must
  add prompt-injection defenses before commit-capable use: reject
  system/developer/tool/secret-seeking instructions, parse a narrow intent
  schema, validate against Application policy, show preview and require
  explicit confirmation.
- Settings now separate food text edits from store source management. The
  accepted direction is not to ask the user to type store names; stores are
  represented as managed sources backed by separate Hermes skills, with
  schedule/manual refresh visible in the UI. Sources are not all enabled by
  default; the user chooses only needed stores. If 2+ sources are selected,
  shopping items are grouped by store. This is UX-only; Stage 10.5 still does
  not run store skills or fetch store pages, prices or availability.
- Hermes was restarted and a fresh launcher was sent to live Telegram after
  the settings-text routing fix on 2026-07-13.

## Callback policy

Accepted callback shape:

```text
cl:<clarify_id>:<choice_index>
```

Properties:

- `cl:*` is handled by the installed Hermes Telegram adapter.
- User-visible button text is a Russian action label, for example
  `Составить меню`, `Изменить меню` or `Покупки`.
- Callback data contains only a stable clarify id and numeric choice index.
- Full operation payloads, profile data, menu data, secrets and private ids are
  not placed in callback data.
- Repeated navigation is safe because screen rendering is demo-only and
  idempotent.

Rejected callback shapes:

```text
ux:*
dm:*
pv:*
```

Reason: not handled by the installed Hermes Telegram adapter.

## Final Stage 10.5 result

Status: accepted for first-version UX/UI planning on 2026-07-13.

The accepted first-version product UX/UI is:

- narrow Telegram Menu Planner bot, not a generic prompt box;
- empty home starts menu planning with `Составить меню`;
- active home shows current meal/recipe context, remaining shopping items,
  `Покупки`, `Рецепт`, `Изменить меню` and `Настройки`;
- menu editing is text-first and always leads to a preview before save;
- food settings use text-first edits, while store price sources are managed
  as selectable Hermes-backed sources;
- shopping lists are grouped by source when two or more price sources are
  selected;
- no global `Закрыть` inline button is shown in normal menus.

Safety settings locked for the next stage:

- text input is allowed only on declared text-first screens;
- text on button-only screens is blocked inside the Menu Planner adapter and
  is not forwarded to the generic Hermes agent;
- text-first screens require prompt-injection defenses before production
  commits: user text is data, not instructions; system/developer/tool/secret
  requests are rejected; only narrow intent schemas are parsed; Application
  validation, preview and explicit confirmation are mandatory;
- callback data remains short stable ids only, without full payloads, private
  data or secrets;
- Telegram cannot commit state directly without Application preview,
  confirmation, version/hash and permission checks.

The current full-screen live smoke can be initiated by pressing the launcher
button or sending this exact text to the live Hermes Telegram bot:

```text

```

The bot then serves demo screens with text-labeled inline buttons backed by
Hermes-compatible `cl:*` callback data.
